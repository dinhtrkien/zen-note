ZEN NOTE — ONE-FILE MIGRATION FROM YOUR OLD V1 PROJECT

This ZIP is NOT a .swiftpm project. Its code files are loose, visible files.
Use this only in the ORIGINAL old project that still shows your books/notes.
Do NOT paste it into the new v2 project. Do NOT add a second ContentView file.

1. Finish writing in the old app, return to Books, wait for autosave, then stop
   running the app. Keep the original project and bundle identifier unchanged.
   Duplicating project source alone does NOT back up private study data.

2. Transfer ZenNote-v1-Migration.zip to the iPad and extract it in Files.
   Open ContentView.swift.txt, select all its text, and copy it.
   The .txt and .swift files contain the SAME complete replacement code.
   If Files won't let you copy the text, use Apple's Shortcuts app:
     - Create a shortcut with Select File (single file).
     - Add Get Text from Input using the selected file.
     - Add Copy to Clipboard using that text.
     - Run it and select ContentView.swift.txt.
   This fallback copies text only. It does not modify any project or notes.

3. Open the ORIGINAL old project in Swift Playgrounds. Open its existing
   ContentView.swift in the sidebar. Select ALL existing code, delete it, and
   paste the complete replacement. Change no other file or app setting.
   Keep an original source copy in case you need to undo the code edit.
   After pasting, verify the body is replaced: inside `var body`'s `ZStack` the
   first line reads `mainContent`, and no `if let session = app.session` block
   remains there.

4. Run the ORIGINAL project. Check that your OLD books are still visible.
   If it fails to compile or the old list is empty, STOP and report the error.
   Do not delete the project, import replacements, or assume migration worked.
   This helper still requires a rebuild; sandbox persistence is device-dependent.
   If the previous closing-brace error bubble is still visible after a full
   replacement, press Stop, close the project from the Playgrounds Home screen,
   reopen it, and run again before reporting it.

5. In Files, create an EMPTY local folder such as ZenNote-Library in a location
   outside Swift Playgrounds-owned storage. Choose On My iPad storage where
   available for offline use. Don't choose the folder containing these ZIP files.

6. Back in the old app's Books screen, tap Copy library to Files. Select that
   EMPTY folder. Keep the app in front until copying/verification finish.
   Save errors must be retried first. Existing destination files are refused.
   PDFs, editable drawings, links, metadata, and preferences are copied.
   A success message reports the verified book/file counts. Original data is
   NOT deleted. No success message means no confirmed migration.

7. Transfer/extract ZenNote-iPad.zip (the NEW v2 app). Open its ZenNote.swiftpm
   as a new project. Tap Choose Files folder, select the EXISTING folder you
   exported into, and confirm Use folder. It opens the library, not an empty one.

8. Check several old notes AND PDF annotations; stop/relaunch and recheck.
   Keep the original old project until everything is verified. Copy the WHOLE
   Files library folder to another location after saves finish as a backup.

Future versions can be opened as fresh projects and reconnected to that same
Files library; no repeated source-by-source migration is needed.

HOST STATUS: The helper passes a native Apple-framework compile check on a macOS
runner (Xcode 16.4, iOS 18.5 simulator SDK, Swift 5 mode), including the
SwiftUI/UIKit branch and the NSFileCoordinator path. Folder permissions, the
actual copy/verification, and live data persistence must still be checked on
your iPad. No new automated tests or test runs are part of this handoff.
